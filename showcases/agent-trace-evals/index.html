agent-trace-evals

Evaluate tool-using LLM agents and RAG pipelines the way they fail: stochastically and through their traces. Python + strict TypeScript, MIT.

What is in it

  • Trace-based agent evals (standard-library Python): assertions on tools called, order, retrieval before answer, citations, latency/cost budgets; pass rate with a Wilson 95% lower bound per case.
  • RAG module (numpy + fastembed, CPU only): BM25 and dense retrieval, hybrid fusion (RRF), cross-encoder rerank with bge-reranker-base (MIT). jina-reranker-v2 is shown as a comparison only: it scores higher here but its licence is non-commercial (CC-BY-NC-4.0).
  • Pipeline checks: a refusal gate on the rerank score, citations must point to retrieved documents, a lexical faithfulness check, one JSONL trace per query.
  • TypeScript port (strict): retrieval and metrics only (BM25, dense, RRF, recall/MRR/nDCG, citation check), with tests asserting the same numbers as Python. Plus a TS tool router with budgets and fallbacks.

Caveats: one run per configuration on 30 queries; the gate threshold and other settings were tuned on the same queries (no held-out set). The bge reranker does not beat dense retrieval alone on this small set. Faithfulness is a conservative lexical check, and answer accuracy is a lenient key-fact match. This is a demonstration of the engineering pattern, not a benchmark.

How it was built

Built by Markus Isaksson with AI assistance: Grok Bot wrote specs and code, other models proposed patches, and the module went through several rounds of read-only AI review (scored on correctness, honesty of claims, eval methodology and licensing). Fixes were integrated until the reviewer rated it publishable. Tests re-check the published results against the recorded traces.
